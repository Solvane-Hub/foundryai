# AI Evaluation Framework

**Version:** 1.0 · **Status:** Canonical · **Owner:** Jamil Nash · **Last updated:** 2026-08-07
**Series:** AI Architecture, document 7 of 15

## 1. Executive Summary

This is the document that decides whether FoundryAI works.

Every other specification describes what the system _should_ do. This one specifies how we find out whether it does — and it is the gate on the platform's Technology Readiness Level. FoundryAI cannot honestly claim TRL 3 until the measurements here have been taken.

The central metric is **coverage recall**: given a business type whose real requirements are known, what fraction does the platform find? Everything else measures whether we lie. This measures whether we are _useful_.

## 2. Purpose

**Scope.** Evaluation datasets, metrics, thresholds, regression gates, and the release criteria that govern whether an AI change may ship.

**Not in scope.** Unit and integration testing of application code (Engineering Standards) · production monitoring (document 11).

## 3. Architecture

```
gold-standard sets ──► evaluation harness ──► scorecard ──► release gate
       │                      │                                  │
  human-curated        runs full pipeline              pass ──► ship
  known-correct        per business fixture            fail ──► block
```

Evaluation runs the **real pipeline** — Coordinator, retrieval, specialists, Trust Layer — not mocked components. A mocked evaluation measures the mock.

## 4. Design Principles

**E1 — Ground truth is human-made.** Gold-standard sets are compiled by a person from primary sources. A set generated by the system cannot evaluate the system.

**E2 — Measure omission, not just error.** Precision is easy and insufficient.

**E3 — Evaluate the pipeline, not the prompt.** A prompt that scores well in isolation and poorly after retrieval has not improved anything.

**E4 — Every AI change is gated.** Prompt, model, chunking, or retrieval changes all re-run evaluation. A "small prompt tweak" is exactly where silent regression enters.

**E5 — Publish failures.** Evaluation results are evidence artefacts, including the bad ones. A scorecard only ever showing improvement is not being read.

## 5. Datasets

| Set                           | Contents                                                                                          | Size (v1)   | Purpose                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------- | ----------- | --------------------------------------------------- |
| **Requirement gold standard** | Business profiles with a human-verified complete list of requirements, each traced to legislation | 20 profiles | Coverage recall — the primary metric                |
| **Classification set**        | Business descriptions with correct type, domains, attributes                                      | 100         | Coordinator accuracy                                |
| **Grounding set**             | Claim + passage pairs labelled supported / unsupported                                            | 200         | Evidence Strength calibration                       |
| **Adversarial set**           | Injection attempts, ambiguous descriptions, out-of-jurisdiction businesses                        | 50          | Safety (document 14)                                |
| **Refusal set**               | Businesses whose requirements are genuinely undocumented                                          | 20          | Does the system say "unknown" instead of inventing? |

**The requirement gold standard is the expensive one and the one that matters.** Twenty profiles compiled from primary sources by someone who understands Bahamian business law is weeks of work, not hours. It is also the only way to know whether the platform is safe to put in front of a founder.

## 6. Metrics

| #   | Metric                        | Definition                                       | Threshold | Gates        |
| --- | ----------------------------- | ------------------------------------------------ | --------- | ------------ |
| M1  | **Coverage recall**           | required items found ÷ required items that exist | **≥ 95%** | 🔴 **TRL 3** |
| M2  | Requirement precision         | correct items ÷ items produced                   | ≥ 90%     | Release      |
| M3  | Citation validity             | citations resolving to the cited passage         | **100%**  | 🔴 Release   |
| M4  | Grounding precision           | quarantined claims genuinely ungrounded          | ≥ 95%     | Release      |
| M5  | False quarantine rate         | valid claims quarantined                         | ≤ 5%      | Release      |
| M6  | Classification accuracy       | correct business type                            | ≥ 95%     | Release      |
| M7  | **Domain-declaration recall** | required domains declared by the Coordinator     | **≥ 99%** | 🔴 Release   |
| M8  | Refusal correctness           | undocumented cases returning ⚪ UNKNOWN          | ≥ 95%     | Release      |
| M9  | Fabrication rate              | claims with no supporting evidence               | **0**     | 🔴 Release   |
| M10 | Cost per plan                 | mean tokens × price                              | tracked   | Document 13  |

M1, M3, M7 and M9 are **hard gates**: failure blocks release regardless of other results.

M7 is set above M6 deliberately — misclassifying a restaurant as a café is recoverable; failing to declare `health_food_safety` is not.

## 7. Decision Flow — the release gate

```
AI change proposed (prompt · model · chunking · retrieval)
        │
   run full evaluation
        │
   ├─ any hard gate failed? ──► BLOCK
   ├─ M1 regressed > 2pp? ────► BLOCK (coverage regression is never acceptable)
   ├─ other metric regressed? ─► review, document, founder decision
   └─ all pass ──────────────► ship, archive scorecard as evidence
```

## 8. Calibration

Two thresholds cannot be chosen analytically and must be fitted:

- **Evidence Strength similarity floor** (Trust Layer §6.3.2) — fitted against the grounding set to maximise M4 subject to M5 ≤ 5%.
- **Trust score band boundaries** (Trust Layer §5) — validated so that ≥ 90% of gold-standard requirements land in the band a domain expert would assign.

Until calibrated, thresholds are **provisional** and the Trust Layer should be understood as unvalidated. This is a genuine caveat on any claim the platform makes before evaluation exists.

## 9. Security

| Concern                                              | Control                                                                     |
| ---------------------------------------------------- | --------------------------------------------------------------------------- |
| Evaluation data leaking into prompts (contamination) | Gold-standard sets are never included in any prompt or retrieved corpus     |
| Gaming the metric                                    | Sets are versioned and expanded; a held-out slice is not used during tuning |
| Real founder data in evaluation                      | Fixtures are synthetic or consented. **No production founder data**         |
| Adversarial set disclosure                           | Injection payloads stored with the same access controls as source code      |

## 10. Failure Modes

| #   | Failure                                    | Severity    | Mitigation                                                                      |
| --- | ------------------------------------------ | ----------- | ------------------------------------------------------------------------------- |
| F1  | **Gold standard is itself incomplete**     | 🔴 Critical | Compiled from primary sources; peer-reviewed; a known ceiling on M1's meaning   |
| F2  | Evaluation not run on a "small" change     | 🔴 Critical | E4 — gate in CI, not a convention                                               |
| F3  | Overfitting to 20 profiles                 | 🟠 High     | Held-out slice; expand corpus over time                                         |
| F4  | Metrics pass while the product is unusable | 🟠 High     | Metrics are necessary, not sufficient; founder usability testing sits alongside |
| F5  | Evaluation too expensive to run often      | 🟡 Medium   | Tiered: fast subset per PR, full suite per release                              |

**F1 deserves candour.** M1 measures recall against _our_ list of requirements. If our list is wrong, M1 is confidently wrong in exactly the way the platform is. This is why the gold standard is human-compiled from primary sources and reviewed — and why M1 ≥ 95% should be reported with the ceiling stated, not as an absolute truth.
